# Eval run, 27 October 2026: the HEARTS scenarios

The eight scenarios added in PRs #37 and #38 (ai-use-note,
ai-tools-consent, read-hardest, identifiers-in-transcript,
group-assumption, quote-descriptor, house-style, template-given), run
under the rules in `evals/README.md`. They came from mapping Magpie to the
HEARTS scorecard (Loosbrock, K. (2025). The HEARTS Framework: Six lenses
for evaluating AI-assisted UX research. Hey Kaleb & Co.
https://www.heykaleb.com/hearts-framework). No other scenarios were run.

## How it was run

- **Adapter and commit:** `adapters/skill/magpie/` at 5f547d1 (main after
  PR #38), copied to `.claude/skills/magpie/` in an empty folder outside
  the repo. Each run got its own fresh folder.
- **Assistant and platform:** Claude Code 2.1.312, `claude -p` with
  `--output-format stream-json`, one fresh session per run with its own
  `--session-id`. Each later turn resumed the same session by id. The
  model was the one Claude Code used by default in this container; this
  run doesn't name it.
- **How Magpie was started:** the first message of every session began
  with `/magpie`. Proof per session: the "Magpie is on" line opened the
  first reply, every reply ended with the status line, and the session
  trace shows `operating.md` and the stage file being read. All 24 scored
  sessions passed all three checks.
- **Answers kept out:** the session folder held only the skill and the
  scenario's input files. Project memory, the notes directory and the
  extra directories were turned off by unsetting `CLAUDE_MEMORY_STORES`,
  `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE`,
  `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD`,
  `CLAUDE_ADDITIONAL_DIRECTORIES` and `CLAUDE_CODE_SESSION_ID`. Sessions
  could not see the scenario files, the standards or this repo.
- **Loading check failed on purpose:** read-hardest, run once in a folder
  with no skill and no `/magpie`. The reply had no "Magpie is on" line,
  no status line and no skill reads, so the check catches a session
  without Magpie. This control is also used below to judge read-hardest.
- **Model judge:** the same model family as the assistant (the Claude
  session that ran the batch, reading each full transcript against the
  pass and fail lists). That is the limit the README warns about. Every
  verdict below says what it rests on.
- **Person judging:** not yet. Kirsten is owed at least ten replies to
  judge, chosen to include every partial and the one missed review.
  Suggested set: all three read-hardest runs and the control,
  template-given run 2, and one each of the other six scenarios.
- **Replies saved at:** `/mnt/project-files/eval-runs/2026-10-27-hearts/`
  in the project's shared folder (outside the repo). Each run has two
  files: `<scenario>-run<n>.md` with each turn's final reply, and
  `<scenario>-run<n>.full.md` with all of Magpie's text, its tool calls
  and every file it wrote. Judge from the `.full.md` file (see below).
- **Bash and Write approvals:** in `-p` mode the sessions could not get
  approval to run the check scripts, and file writes were refused in many
  runs. Magpie said so each time, checked quotes and counts by hand, and
  wrote its drafts to its own scratch folder or into the reply. No
  verdict below depends on a script having run.

### Two things about the harness

1. **The final reply isn't the whole turn.** At stages 6 and 7 Magpie
   starts the independent review in the background. The stream's
   "result" then held only the message Magpie wrote after the review came
   back, not the draft before it. The `.full.md` files were rebuilt from
   each session's full trace so that nothing is judged from half a turn.
   The scripted follow-up turns also fired in some runs where they
   weren't needed, because the script looked only at the last message.
   Where that happened, the extra turn isn't scored.
2. **A container restart stopped the batch** after 16 of 25 runs. The 9
   unfinished sessions were thrown away, not scored, and run again from
   scratch in fresh folders.

### Inputs the scenarios needed

The scenario files describe their material without supplying it, so this
run wrote it, based on the Sparrow fixture (`evals/fixtures/`):

- the Sparrow transcripts and findings, a copy of the findings with one
  planted group assumption ("servers are less comfortable with technology
  than managers"), and a copy of the transcripts with a full name and an
  email address added to P3;
- Sparrow study records set up for a report and for a house-style
  readout, one with a team template already saved;
- a Brightpay study record whose plan names an AI transcription tool and
  Magpie for analysis, and eight short Brightpay transcripts with role and
  company type (P7 is the one CTO at an enterprise).

They're saved beside the replies as `inputs/`.

## What this run shows

- The new rules behaved as written three times each: the "How AI was
  used" section, the consent check covering AI tools, the "Read hardest"
  line, placeholders for personal details, the review question on group
  assumptions, role and company type on quotes, the house style, and not
  re-asking for a saved template.
- The read-hardest partial is about the clean fixture, not the new line.
  Magpie, and the same assistant without Magpie, find problems in clean
  Sparrow findings that aren't there. Two possible fixes: add a rule to
  stage 6 that a check which finds nothing wrong says so and changes
  nothing; or loosen the scenario to judge only the "Read hardest" line.
  The first is the real fix if Kirsten wants Magpie to leave good work
  alone. Kirsten's call.
- The independent review on a report didn't start by itself in 1 of 9
  report and readout runs (template-given run 2). An earlier check
  of the review triggers (before PR #35) found the same kind of miss
  once in five. Worth watching, not yet a pattern.

## What this run does not show

- Claude.ai and Gemini: not tested. The skill ran only in Claude Code.
- The code checks running, including the quote check accepting
  placeholders: they needed approvals the `-p` mode didn't grant.
- A person's verdicts. The model judge is the same family as the
  assistant.
- The other scenarios and the three fixtures.
