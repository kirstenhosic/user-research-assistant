# Eval run, 27 October 2026: the coaching scenarios

The seven scenarios added in PR #25 (challenge-reason, vague-words,
your-turn-decision, you-do-it, theme-review, method-reasoning,
question-order), run under the rules in `evals/README.md`. The twelve
scenarios added in PRs #20 and #24 were not run here.

## How it was run

- **Adapter and commit:** `adapters/skill/magpie/` at 85b326d (main after
  PR #25), copied to `.claude/skills/magpie/` in an empty folder outside
  the repo.
- **Assistant and platform:** Claude Code 2.1.311, `claude -p` with
  `--output-format stream-json`, one fresh session per run. Each later
  turn resumed the same session by id. The model was the one Claude Code
  used by default in this container; the session trace shows it only as
  the assistant, so this run doesn't name it.
- **How Magpie was started:** the first message of every session began
  with `/magpie`. Proof per session: the "Magpie is on" line opened the
  first reply, every reply ended with the status line, and the session
  trace shows `operating.md` and the stage file being read (by `cat` or
  `Read`). All 21 scored sessions passed all three checks.
- **Answers kept out:** the session folder held only the skill. Project
  memory, the notes directory and the extra directories were turned off
  by unsetting `CLAUDE_MEMORY_STORES`,
  `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE`,
  `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD` and
  `CLAUDE_ADDITIONAL_DIRECTORIES`. Sessions could not see the scenario
  files, the standards or this repo.
- **Loading check failed on purpose:** your-turn-decision, run once in a
  folder with no skill at all and no `/magpie`. The reply had no "Magpie
  is on" line, no status line and no skill reads, so the check catches a
  session without Magpie. A first attempt at this control left the skill
  in the folder, and Claude invoked Magpie by itself through the Skill
  tool, so a real control needs the skill removed, not just uninvoked.
- **Model judge:** the same model family as the assistant (this session,
  reading each reply against the pass and fail lists). That is the limit
  the README warns about. Every verdict below says what it rests on.
- **Person judging:** not yet. Kirsten is owed at least ten replies to
  judge, chosen to include every partial. Suggested set: all three
  challenge-reason runs, all three theme-review runs, and one each of
  the other five.
- **Replies saved at:** `/mnt/project-files/eval-runs/2026-10-27-coaching/`
  in the project's shared folder (outside the repo), one file per run
  with every turn's full text, the session id and the skill files read.
  Three voided batches are kept in subfolders there, explained below.
- **Bash and Write approvals:** in `-p` mode the sessions could not get
  approval to run the check scripts or to write files in some runs.
  Magpie said so each time and checked quotes and counts by hand. No
  verdict below depends on a script having run.

### Three batches were voided and re-run

1. **Shared session id.** The first full batch inherited this container's
   `CLAUDE_CODE_SESSION_ID`, so all 22 child sessions wrote to one
   transcript and `--resume` could pick up another run's turns. Nothing
   from that batch is scored. Fix: unset the variable and pass
   `--session-id` with a fresh UUID per run. Saved under
   `void-shared-session/`.
2. **theme-review's second turn.** The script's second message answered
   context questions and ended "go ahead". Magpie had already produced
   the themes in the first turn, so it read "go ahead" as a skip of the
   theme review, logged it as a risk, and wrote findings. The scenario's
   "looks good" then landed on the findings, not the themes, so the test
   never fired. Those three runs are saved under `void-harness-turn2/`
   and the scenario was re-run with "looks good" as the second turn.
3. **theme-review again.** With "looks good" as the second turn, Magpie
   in two of three runs first asked for the researcher's own patterns
   (the stage 6 your-turn step), so "looks good" landed on that question
   instead of the themes. Saved under `void-harness-turn2b/`. The final
   attempt used a script that sent "you do it" until the reply held the
   themes, then "looks good". Its trigger matched Magpie's planning text
   ("keep, change, split or drop") in runs 1 and 3, so "looks good" went
   out one turn early there and Magpie read it as a yes on the plan. Those
   two sessions were then resumed with "looks good" as a third turn, on
   the themes, and that turn is the one scored. Run 2 fired correctly at
   turn 2. The session ids and every turn are in the run files.

### Inputs the scenarios needed

The scenario files describe transcripts, records and guides without
supplying them, so this run wrote them: one short-form study record for
the Ledgerline admin console study (two research questions, two
hypotheses), eight short transcripts (P1 to P8) that carry the counts the
scenarios name (3 of 8 locations trouble, 2 of 8 paused at permissions,
P5's pause caused by IT, a P3-only audit-log need, P6 supplying most of
the export evidence, 6 of 8 inviting only after setup), a second record
for an exports study, a findings record for stage 7, and two versions of
an interview guide (question 4 hypothetical in v1, question 7 in v2).
They're saved beside the replies as `inputs/`.

## What this run shows

- The your-turn ask, the shown reasoning at stages 3 and 5, the counter
  handling, the hand-back and the vague-word push all behaved as written,
  three times each.
- The theme review's "looks good" guard fired in all three runs, but it
  took three attempts to get the scripted conversation to the themes,
  because Magpie asks for the researcher's own patterns first when it
  can't tell whether they sat in on the sessions. A scripted run needs a
  turn that answers that, or says "you do it", before the test turn.
- The "once per conversation" rule for a principle did not hold in
  challenge-reason when the same mistake came back in a revised draft.
  Two possible fixes: tighten `operating.md` ("Teach as you go") to say
  that a repeat of the same mistake gets a pointer to the earlier
  explanation, not a new one; or loosen the scenario to accept a
  one-clause reminder. The second is closer to how a colleague would
  behave. Kirsten's call.
