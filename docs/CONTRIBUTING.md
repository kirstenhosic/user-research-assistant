# Contributing

Thanks for helping. This file explains how the repository is organized and
what a good change looks like.

## Where things live

- `core/` is the only place research content is written by hand. Everything a
  researcher reads or uses comes from here.
- `adapters/` and `.claude/skills/` are generated by `tools/build.py`. Don't
  edit them directly; your change will be overwritten on the next build.
- `evals/` holds test scenarios. A change to a standard or a stage should come
  with a scenario that would catch it regressing.
- `docs/` holds the design, the provenance record and this file.

## Making a change

1. Edit the files in `core/`.
2. Run `python3 tools/build.py` to regenerate `adapters/`.
3. Run `python3 tools/check.py`. It confirms the adapters are fresh, every
   file reference resolves, every standard has an eval and a recorded
   source, and the code checks pass their fixtures. Fix anything it lists.
4. Commit the core change and the regenerated adapters together.
5. Open a pull request that says what changed and why.

## Standards need a source

If you add or change a standard in `core/standards/`, link it to a public
source and add that source to the table in `docs/PROVENANCE.md`. If there's no
verifiable source, mark the standard as practitioner judgment. Don't cite a
source you haven't checked.

## Writing style

Plain language throughout. Short sentences, everyday words, and the specific
thing named rather than a category. Research terms get a one-line explanation
the first time they appear. See `docs/DESIGN.md`, section "Plain language".

The files in `core/` are also prompts. `docs/PROMPT-STYLE.md` lists the
conventions they follow (one structure, rules with their reasons, each
instruction once, precedence stated) and the platform guidance they come
from. Follow it for any change to `core/`.

## What we don't accept

- Material copied from other tools, courses or internal company documents.
- Anything that collects or stores participant personal data.
- Claims about research practice with no source and no "practitioner judgment"
  label.
